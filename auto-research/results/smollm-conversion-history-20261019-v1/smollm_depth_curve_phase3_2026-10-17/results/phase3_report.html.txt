SmolLM2-135M
One learned curve, four evaluation depths


131,072 training tokens · 4,096 validation tokens · 16,384 test tokens from 16 previously unused test articles


No learned curve passed the predefined validation quality gate in this run. The experiment changes the MLP transformation inside the first block; attention still runs once and all 30 outer transformer blocks remain.



Validation-selected curve:
 Curve · mixed-depth training · N=1. On the fresh test sample, Δ NLL is +0.873086 nats/token, with a 95% document-bootstrap interval [+0.763893, +0.970286]. Perplexity changes by +139.43%; argmax agreement is 57.5%. This is the lowest-KL failed-gate representative, not a successful quality-preserving replacement.


The parameter-matched one-pass width-768 student changes test perplexity by +6.11%. On-demand CPU latency for the selected curve is 0.531× the original first-block measurement and 0.995× the full-model measurement. Quality and runtime are separate outcomes.




What changed from the previous phase


Phase 2 reduced matrix ranks and coefficient resolution while retaining a fixed computational depth. Here, depth t indexes the weights of a SwiGLU vector field. Four learned Catmull-Rom control vectors define gate, up and down matrices over t ∈ [0,1]. The same fitted curve is sampled with N = 1, 2, 4 or 8 Euler steps, with each update scaled by 1/N.


u₀ = 0
F(h,t) = D(t) [SiLU(G(t) RMSNorm(h)) ⊙ U(t) RMSNorm(h)]
uᵢ₊₁ = uᵢ + F(a + uᵢ, i/N) / N
output = a + uₙ


a is the state after the original first attention operation. The original post-attention RMSNorm scales remain frozen and are reused inside F. The depth coordinate now controls computation, rather than indexing a flattened array of weights. This is a chosen continuous-depth construction, not a recovery of an undocumented GSA implementation.

The 16/32/64-step runs are exploratory numerical diagnostics. A model optimized at eight steps need not improve when its ODE discretization is refined. The frozen-state ablation evaluates every field at the original a instead of the evolving a+u; it is not a trained alternative. Runtime and memory accounting


The original first block has 3,540,096 values and 3,538,944 learned projection MACs per token. Each width-192 field evaluation costs 331,776 projection MACs. At eight evaluations the MLP projection count equals the original MLP's; spline assembly, repeated normalization, residual updates and kernel overhead are additional work. Reducing steps reduces this part of compute, not the number of outer blocks or the KV cache size.


On-demand evaluation samples matrices for each step. The optional cached mode keeps N materialized matrix sets in addition to the spline controls; this costs 1.266 MiB per step in FP32. Coefficient storage, sampled-matrix memory and arithmetic counts are distinct. Matrix assembly costs are recorded in the raw accounting. Equal-precision coefficient counts are not compressed-file size comparisons against the original BF16 checkpoint.

Correctness and interpretation limits



The full-width one-step control was bit-identical to the original model.

263 learned tensors outside block 0 remained identical by hash.

Selected-curve cached decoding versus prefill differed by at most 0.000154972076 in logits.

Materialized versus on-demand sampled weights produced exactly matching logits.

All four exported checkpoints are checked against their saved state and measured held-out losses by 
verify_exports.py
.



Training, validation and test use official WikiText-2 article partitions. All articles sampled during phase-2 validation/test are excluded from the corresponding phase-3 evaluation pools. The test set has 16 documents, so the paired 2,000-resample bootstrap intervals have limited breadth. These are pointwise intervals, not simultaneous intervals across all twelve comparisons. The model may have seen WikiText in pretraining. Fixed 128-token windows are not standard full WikiText perplexity. One training minibatch seed is not a seed-robust architecture comparison.


The experiment changes both the MLP representation and its integration depth. Both four-control curves have half the original MLP's parameter budget. The direct width-768 control matches their stored parameters and their four-step projection MACs; the direct width-192 control matches one field's width. The one-step curve accesses only its first control vector. These controls help separate capacity, optimization and recurrence, but do not establish the best possible curve architecture. All selected checkpoints were at the final update, so the bounded training budget does not establish convergence. No conclusions about all-layer conversion, adaptive halting, long-context quality, cache compression or TinyLlama follow from this run.


Next decision


The next experiment should begin with a function-preserving decomposition at full resolution. The original width-1,536 SwiGLU MLP is a sum of neuron contributions: split it into eight width-192 groups, evaluate every group at the same original attention-output state a, and sum the outputs. Algebraically this reproduces the original MLP; its implementation must first meet a floating-point equivalence check. It retains all original MLP weights and is a proposed control, not a measured result in this phase.


Then fit an ordered curve through those contributions and test coarser sampling against that verified reference. Compare keeping a available to each field with the current evolving-state construction, and compare intermediate-path supervision with endpoint-only training. This separates conversion fidelity from the additional compression constraint. Require a curve to beat the parameter-matched direct student and pass the language-quality gate before repeat seeds, longer contexts, broader layer coverage or TinyLlama. Smooth weight functions alone do not establish useful depth invariance.
