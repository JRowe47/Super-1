Curve training compatibility · measured experiment · 17 October 2026

Can a conventionally trained model keep learning in curve coordinates?

Yes in the complete, native-order representation tested here. The important separation is between changing coordinates, changing the optimizer, and restricting the executable model. Pythia learned through full Haar coefficients. Shared-depth toys also learned, but their ceiling performance leaves the deeper GSA capacity question open.

Practical conclusion. Preserve all curve modes and the native optimizer as the conversion baseline. Then test coefficient-space optimization, restrictions, and depth changes independently. The observed copying loss during adaptation occurs in native training too; it cannot be attributed solely to curve conversion.

Pythia: real coefficient gradients, short continuation, paired controls

Each of the 72 tensors in Pythia’s six decoder blocks is flattened in its existing C order and represented by a complete orthonormal Haar pyramid. Every coefficient is retained. Layer identities, attention, token order, nonlinearities and normalization are preserved. Embeddings, the final normalization and the output head stay fixed in every arm. This is a full-resolution parameter representation; it does not yet share curves across Pythia layers.

The curve arms backpropagate through an explicit inverse transform into trainable coefficients. The network runs in float32 using decoded dense matrices, while master weights or coefficients are float64. All Adam runs use learning rate 2 × 10⁻⁵, β = (0.9, 0.999), ε = 10⁻⁸ and zero weight decay, with fresh optimizer states. “Transported Adam” maps coefficient gradients back to native coordinates, maintains native Adam moments, then re-encodes each updated weight tensor.

Adam changes when the coordinates change

The first native and coefficient Adam updates have almost the same Euclidean norm (0.0869715 and 0.0869720), yet their directional cosine is only 0.6390. Transported Adam has cosine 1.0000 with native Adam. This directly connects the earlier component-direction observations to actual learning: equal update size does not imply the same functional intervention.

Exact mathematics, finite-precision implementation

w = HTc    and    ∇cL = H ∇wL,    HTH = I.

With the full orthonormal transform, unpreconditioned SGD commutes with the coordinate change in exact arithmetic. Adam’s coordinatewise second moments generally do not. The transported control preserves the native optimizer mathematically; it is a diagnostic control, not an efficient curve optimizer.

The independently calculated first-step gradient adjoint error is at most 2.67 × 10⁻¹⁵. Native versus curve SGD first updates differ by at most 1.20 × 10⁻¹⁴ per coordinate; native versus transported Adam differ by at most 2.91 × 10⁻¹⁴. The complete initial transform has a maximum float64 reconstruction error of 4.97e-14. There are 9 float32 bitwise mismatches at very small or zero coordinates; tested starting losses and evaluation metrics agree.

The full training trajectories are not bitwise identical. Transported Adam’s installed weights and checked logits match native Adam exactly at sampled steps 1, 4 and 12, but differ at step 24. The small-step SGD control also accumulates differences. These are measured numerical divergences between mathematically equivalent implementations; this study does not isolate their propagation mechanism.

Saved-model verification: both saved native-Adam and coefficient-Adam decoders were independently loaded into fresh checkpoint models. Every recorded validation-block loss, checked retention metric and retained hidden vector reproduced exactly. Re-encoding their saved weights through Haar and back preserved all installed float32 weights and the logits on the checked validation block exactly. This verifies those saved artifacts, not all future update trajectories.

The original SGD setting was unstable

The predeclared SGD learning rate 0.005 produced a first update with norm 0.37824 and maximum coordinate change 0.03840. Native validation loss immediately rose from 4.741 to 7.392, and copying fell below 1%. Both native and curve arms were unstable, with later trajectories diverging strongly. Those runs are retained without replacing their results.

The trigger included observed instability; the rate itself was calculated from the training gradient, without searching validation scores. The original protocol and all original results remain intact. The extra pair uses 48 steps, bringing Pythia’s total to 168.

Shared curves across depth: an explicit toy construction

The second experiment separates a curve over layers from the complete within-tensor representation. It uses all 16 inputs (a,b,c,d) ∈ {−1,+1}⁴ and six binary functions: a, ab, conditional selection between a and b by c, abcd, majority(a,b,c), and bcd. All 96 input-target decisions are trained and evaluated exhaustively. These tests give finite functional coverage, not held-out semantic generalization.

Each model has a 4→16 tanh input map, six residual stages and a six-output readout. Weight fields are W(s) = Σⱼ φⱼ(s)Cⱼ and b(s) = Σⱼ φⱼ(s)dⱼ, where φ₀ = 1/√6 and φⱼ = √(2/6) cos(πjs). All six modes exactly span the original layer weights at the six midpoint locations. Two-mode models retain only modes 0 and 1, keeping full resolution within each weight matrix.

hi+1 = hi + tanh(W(si)hi + b(si)) / N,   si = (i + ½) / N.

The continuous depth field is executed at integer step counts N = 3, 4, 6, 8, 12 and 24. Native off-grid evaluations use the full six-mode interpolant through the trained native layers. This is an Euler-discretized residual model, not a reproduction of the project’s full GSA attention or memory architecture.

All seven final arms reach 100% accuracy at six steps in every seed. All tested final depth/arm combinations also reach 100%, except the full six-mode curve trained from scratch at depth 3, which makes one error across 480 decisions. This apparent success is limited by the small, easy task set.

Conversion changes confidence before it changes decisions

The exact six-mode conversion and the initial bridge match the teacher’s logits to below 10⁻¹¹. Hard two-mode projection discards 26–33% of the residual weight-matrix energy and changes logits substantially, yet already preserves 100% classification accuracy in all seeds at every tested depth, before any continuation. There is therefore no classification deficit here for the bridge to repair.

Discarded energy above is calculated for residual weight matrices, excluding biases. The gradient diagnostic includes both residual matrices and biases, measured at the hard-projected model, and asks how much gradient energy lies outside the retained two-mode subspace. It is not a measure of uniquely lost capability: input/output maps and other retained directions can compensate.

The bridge starts with the discarded modes present as a frozen residual, anneals their multiplier from 1 to 0 over 200 updates, and continues for another 200. Its final architecture equals the hard-conversion model. This run provides no evidence that the bridge improves retention. Likewise, the small difference between two-mode fixed-depth and multi-depth logit drift does not establish a general benefit from multi-depth training.

Why the toy success is inconclusive. A post-hoc check removed every residual stage without retraining. The learned input and output maps still solve 87.5–100% of decisions across all final arms and seeds. The tests do not force substantial depth-dependent computation. They cannot settle whether a restricted GSA regime loses a capability available to vanilla models. Perfect classification also hides meaningful confidence and off-grid function changes.

What this establishes for the curve-space goal

QuestionEvidence from this phaseRemaining boundary
Does classical training make exact curve encoding incompatible?No incompatibility appeared in the complete native-order representation. Real coefficient gradients support learning; independent reload checks pass.This retains the original architecture and all degrees of freedom. It does not test a restricted GSA function class.
Can continuing training damage retained behavior?Yes. Ordinary and coefficient Adam both improve text loss while degrading copying and the prose probe.Conversion alone does not explain the damage. There is no replay or teacher-preservation objective here.
Does coefficient-space training behave differently?Yes. Adam changes update direction despite almost identical first-step norm.One transform, fixed learning rates and a single short data stream cannot identify an optimal curve optimizer.
Do shared depth curves lose important functions?The small two-mode models fit every finite toy label. Projection changes logits even when labels survive.The toy tasks are too easy; no conclusion about long-context recall, compositional depth or full GSA expressivity follows.
Does continuous parameter depth give interchangeable execution depths?A defined depth field permits multiple execution counts, with high toy accuracy.Exact function preservation is only built in at the original sample grid. Logits vary with execution depth; continuous adaptive stopping was not tested.

The complete representation is an appropriate starting point for curve-level training research. Imposing shared low-dimensional fields or changing the memory/attention operator is a separate architectural step. Failures there could reflect representational restrictions, insufficient optimization, or an unstable conversion path; this phase does not conflate those possibilities.

The next informative experiment is a bounded retention-aware continuation comparison: native versus complete-curve updates with the same replay or teacher-preservation budget, then selected multiscale coefficient constraints. Judge new-task learning at comparable retained performance. In parallel, replace the saturated toy suite with sequence tasks that require explicit binding, composition or memory, including length generalization and a strong shallow control. Only then compare hard conversion, a residual bridge and training from scratch under matched parameter and execution budgets. These follow-up experiments have not been run in this bundle.

Methods, provenance and reproduction

The starting model is EleutherAI/Pythia-70m, immutable commit de3e4e2d6cbb3b1a51f90fe153ea51fcd8c7c852, step 143000. The model file SHA-256 is 737de0ce1e32a9559925b452921cdea0b12d3932133b6b0b70b61a351b9f6272. Other checkpoints were examined in preceding phases; this phase uses only the final checkpoint.

Continuation data comes from WikiText-2 raw, pinned revision b08601e04326c79dfdd32d625aee71d232d685c3. The deterministic selection contains 48 training blocks and 24 validation blocks of 96 tokens from distinct source rows, with seed 2026101709. Every arm sees the same 24 batches once: 4,608 token positions or 4,560 next-token targets. Validation contains 2,280 targets. WikiText is not verified absent from Pythia’s original pretraining.

The copying probes contain 24 newly generated sequences, excluding token IDs used by the preceding intervention probes. The eight original prose passages contain 284 next-token targets and are reused from that phase. Synthetic successor copying is a targeted behavioral probe, not a full language-capability evaluation. The initial checkpoint, dataset hashes, exact selected token IDs, probe IDs, per-item scores, trajectories, coefficients for the toy models, final native/curve-Adam decoder weights, and all runnable source are included or pinned.

Timing totals are 209.64 seconds for the original Pythia arms, 74.95 seconds for the additional SGD pair and 44.84 seconds for the toys. These are component wall times; some execution overlapped. Pythia uses three CPU threads and the toys one. There is no GPU run, no broad sweep and no claim of curve execution speedup: matrices are decoded and multiplied densely.

The environment used Python 3.12.14, PyTorch 2.14.1+cpu, NumPy 2.3.5, Transformers 4.57.1, Safetensors 0.8.0, PyArrow 19.0.1 and Matplotlib 3.10.8. Numerical identity across other software or hardware is not guaranteed. A rerun overwrites result files, so use a copy of the extracted bundle.
